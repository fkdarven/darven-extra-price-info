### RED → GREEN findings during release QA

1. The full JS suite initially failed because `admin/src/settings/__tests__/app.test.js` still searched for the pre-i18n tab label `Visual`, while the canonical source msgid is `Display`. The runtime and POT/PO already used `Display`; the test was corrected. Focused GREEN: 5/5 tests. Full GREEN: 47/47 tests.
2. PHPCS initially reported two inherited fixable findings previously documented by Task 8: indentation in `InstallmentPriceFormatter.php` and mixed-line-ending/comma spacing in `TextDomainLoader.php`. Both were corrected mechanically. Full PHPCS then returned 0.
3. Manual product QA found a release-blocking false-positive: the REST request returned “Product options saved.” but no meta reached the database. Root cause: `ProductSettingsRepository::save()` updated the `WC_Product` object in memory but never called `$product->save()`.
   - RED: focused repository test failed, `0 is identical to 1`, proving no persistence call.
   - First GREEN attempt exposed two existing fallback tests that correctly guard against double-saving in `woocommerce_admin_process_product_object`.
   - Final minimal fix: repository saves by default for REST; the classic WooCommerce fallback passes `persist=false` because WooCommerce performs the standard save afterward.
   - Impacted GREEN: 23 tests, 80 assertions. Full GREEN: 134 tests, 1,766 assertions.
   - Real database GREEN: authenticated PUT returned 200 for simple and variable products, and both persisted canonical schema 1 plus the two legacy mirrors.
4. Independent release review found that the first supposedly runtime-only ZIP still contained `public/js/frontend.test.js`. The initial manual forbidden-path expression checked test directories but not colocated `*.test.js` basenames, so the earlier “zero forbidden paths” result was incomplete.
   - RED: `ReleasePackageTest::test_builds_a_runtime_only_distribution_archive` failed explicitly on `darven-extra-price-info/public/js/frontend.test.js`.
   - Minimal fix: exclude `*.test.js` during staging and reject it again during final ZIP validation.
   - Focused GREEN: 1 test, 1,346 assertions. Package/metadata GREEN: 12 tests, 1,387 assertions, 1 skip. Full GREEN: 134 tests, 1,813 assertions, 1 skip.
5. npm 11's dependency warning was traced to both unreviewed install scripts and the stale transitive graph in `@wordpress/scripts` 27.9.0.
   - RED: the initial audit reported 28 vulnerabilities and four unreviewed install scripts.
   - The build toolchain was upgraded to `@wordpress/scripts` 34.0.0, reviewed install scripts were pinned or denied explicitly, strict enforcement was enabled, and narrow patched transitive overrides were added.
   - The upgrade initially failed because legacy per-file JSX pragmas conflict with the new automatic runtime. Removing them made JS green but caused the PHP manifest guard to fail because `react-jsx-runtime` is unavailable on the declared WordPress 5.0 minimum.
   - Final fix: a project Babel configuration keeps classic `createElement` output without legacy per-file pragmas. GREEN: 7 JS suites/50 tests, 153 PHP tests/2,004 assertions/2 skips, 0 audit vulnerabilities, and no unreviewed install scripts.
6. The 2026-08-24 advisory refresh found two new high-severity transitive development advisories after a fresh locked install.
   - RED: `npm audit --json` identified `js-yaml` below 4.3.1 through `cosmiconfig` and `nanoid` below 3.3.18 through `postcss`.
   - Minimal fix: compatible narrow overrides for only the affected dependency paths.
   - GREEN: a second fresh install audited 1,493 packages with zero vulnerabilities; all 62 JavaScript tests and both admin builds passed.
7. Authenticated browser smoke on WordPress 7.1 exposed ReactDOM's legacy-root deprecation warning in the settings and product-option entrypoints.
   - RED: the new product-entrypoint regression expected `createRoot` to be preferred but observed one legacy `render` call.
   - Minimal fix: both entrypoints prefer WordPress's React 18 `createRoot` API and preserve `render` only as a compatibility fallback for older supported WordPress versions.
   - GREEN: focused entrypoint tests passed 4/4; the full matrix passed 8 suites and 63 tests. Fresh settings and product-editor tabs showed no plugin console warnings.
